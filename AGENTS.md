# AGENTS.md

## Project

**Photo Collage Editor** — a single-page photo collage editor that runs entirely in the browser.

- Opens directly from disk (`file://`) with no build step and no install.
- Pure vanilla JavaScript, HTML, and CSS. No frameworks, no bundler, no package manager.
- Offline by design: no network requests, no CDN links, no analytics, no remote fonts.
- Photos never leave the machine. All work happens in memory / `localStorage`.

## Current state

## Hard constraints

1. **No dependencies.** Do not add npm packages, vendored libraries, or remote script/style/icon URLs.
2. **Works from `file://`.** Do not use ES `import` / `export` or `fetch()` for local assets — browsers block both on the `file:` protocol. Use classic `<script>` tags in dependency order.
3. **No network I/O.** No `fetch`, `XMLHttpRequest`, WebSockets, or remote images.
4. **No generated artifacts in git.** No `node_modules`, dist bundles, or exported collages.

## UI specification (v1)

### Page structure

On load the editor area shows a **format start screen**: the heading `Select format:` above five buttons (9:16 Status, 16:9 Banner, 7:9 Portrait, 5:4, 1:1 Square), each with its icon, ratio, optional name, and pixel size. The action bar and canvas stay hidden until a format is chosen. Choosing one starts the editor and does not offer the start screen again for that session.

While editing, two stacked regions fill the viewport height, no page scrolling:

1. **Action bar** — fixed height (~56 px) at the top, dark background. Contextual tool icons sit on the left; the always-visible **row/column toggle**, **border-thickness button**, **margin-color picker**, and **Save** button sit on the right. The contextual area is empty when nothing is selected.
2. **Editor area** — fills the remaining height, dark gray background (`#2b2b2b`). Centered inside it: the collage canvas, with add-group buttons and add-box rails arranged according to the current mode.

### Row and column modes

- A permanent action-bar toggle switches between **row mode** and **column mode**, showing `space_dashboard` upright in column mode and rotated 90° counter-clockwise in row mode. The switch is exposed through the button's label and title.
- Distinct portrait formats (9:16, 7:9) start in **row mode**; landscape formats (16:9, 5:4) start in **column mode**; 1:1 starts in row mode. The chosen canvas size never changes with the mode.
- Row mode is the horizontal model: groups stack top to bottom, boxes run left to right within each group, add-group buttons sit above and below, add-box buttons sit left and right, group boundaries are horizontal, and box boundaries are vertical.
- Column mode is the same weighted model transposed: groups run left to right as columns, boxes stack top to bottom within each column, add-group buttons sit left and right, add-box buttons sit above and below, group boundaries are vertical, and box boundaries are horizontal. The canvas itself keeps its format.
- The lock rules are per group, so they apply per column in column mode: the `n − 1` cap, the shared aspect-ratio reference, and the disabled boundary next to a single-box locked group all follow the columns.
- A single-box aspect-locked group still spans the full cross axis, which means the full canvas height in column mode. Square locks derive the box's other side from the group's cross-axis size in either mode.
- Switching modes turns the structure 90°: row → column is clockwise (the top row becomes the right column) and column → row is counter-clockwise (the right column becomes the top row). Box order inside each group is preserved, so the leftmost box becomes the topmost.
- The turn freezes the current pixel proportions into the weights first, releases every ratio lock before the structure moves, and never rotates or resets the photos themselves. Their zoom, pan, and rotation survive; only the box shape changes.
- Switching modes clears the current box selection, so the selection border, ghost, and zoom/rotate circles do not follow the box into the new layout.
- No animation is used for the switch.

### Layout metrics

Define once as CSS custom properties on `:root` and mirror them in JS constants:

| Token | Value | Meaning |
| --- | --- | --- |
| `--canvas-w` / `--canvas-h` | from the chosen format | Logical canvas size; 1080 px on the shorter side, the longer side from the ratio: 9:16 → 1080 × 1920, 16:9 → 1920 × 1080, 7:9 → 1080 × 1389, 5:4 → 1350 × 1080, 1:1 → 1080 × 1080. Set when the format is chosen; never changes with content. Matches the export size. |
| `--canvas-pad` | 5 px default, 0–100 px | Padding inside the canvas, all sides, showing the canvas paint. Set by the border-thickness slider; 0 removes it |
| `--gap` | 5 px default, 0–100 px | Margin around every image box, showing the canvas paint, set by the same slider. At 5 px adjacent boxes show 10 px between them, and the canvas edges show 5 px padding plus 5 px margin; at 0 the photos touch and the canvas background is hidden |
| `--placeholder` | `#d9d9d9` | The empty-cell gray on white. Grid cells and empty free-form boxes both paint it through `--placeholder-fill` (`rgb(207 207 207 / 80%)`) so that 80% of `#cfcfcf` over a white canvas lands back on `#d9d9d9`: the 20% transparency is invisible on white and only tints the cell on a painted margin. Only the translucent free-form selection ghost keeps the plain hex, because it already carries its own opacity. The same values reach the export |
| `--canvas-bg` | `#ffffff` | Sampled solid margin color, used as the fallback where a free-form frame hangs outside the canvas; configurable with the action-bar picker |
| `--canvas-paint` | vertical `#f5f2eb → #dfd6c7` | Canvas background paint: a color for Fill, a CSS gradient for the three linear/radial styles, or the seeded spots bitmap. Starts as the **Warm Stone** preset, top to bottom |
| `--canvas-paint-image` | `linear-gradient(180deg, #f5f2eb, #dfd6c7)` | The paint as a background image (`none` for Fill), reused by free-form frame rings |
| `--canvas-swatch` | split `#f5f2eb` / `#dfd6c7` | Margin-button preview: the color, or a left/right split of the two gradient stops |
| `--page-bg` | `#2b2b2b` | Page background around the canvas |
| `--accent` | `#1e88e5` | Selection border, row-line highlight |

The canvas keeps its logical pixel size; it is visually scaled down (CSS `transform: scale()`, centered) to fit the available viewport space. All editor math uses logical pixels, so behavior is identical at any zoom. The real `<canvas>` is only used for export — the editor UI itself is DOM elements.

### Rows and image boxes

- Initial state after choosing a format: **two groups**, each containing **one empty placeholder box**. Portrait and square formats call these rows; landscape formats call them columns.
- In row mode a group is a horizontal track inside the canvas; boxes fill it left to right, like a flex row with wrapping disabled. In column mode the same group is a vertical track; boxes stack top to bottom.
- Image boxes are white on the outside (5 px margin by default, set by the border-thickness slider) with a light gray placeholder fill that is 80% opaque `#cfcfcf`, tuned so the empty cell looks exactly like the old solid `#d9d9d9` on a white canvas while a painted margin shows faintly through; once populated, the photo covers the box, cropped to the box aspect ratio and centered (`object-fit: cover`), clipped by the box. At the default thickness, adjacent boxes have 10 px of white between them, and the canvas edges have 5 px padding plus the 5 px box margin.
- Empty boxes show a centered `add_photo_alternate` icon as a visual hint; loading a photo replaces it.
- **Add box:** a button beside each group, using `add_circle.svg`. In row mode the buttons sit on the left and right of the canvas, vertically centered on the row. In column mode they sit above and below the canvas, horizontally centered on the column.
- **Add group:** buttons outside the canvas, using `add_circle.svg`. In row mode they sit above and below and add a row (top inserts at the top, bottom appends). In column mode they sit to the left and right and add a column (left inserts at the left, right appends). A new group always starts with one empty box.
- No minimum number of groups: deleting the last box in the last group leaves an empty editor area, with the add-group buttons still usable.

### Free-form layer

- A **free-form layer** sits above the weighted grid, so its photos and text boxes can overlap the rows/columns, their gaps, and each other. It is independent of row/column mode.
- **Add free photo:** a button with `add_box.svg` at the canvas's top-left corner, outside the canvas with the same 12 px gap and 32 px size as the add-group/add-box buttons. It is always top-left, in both modes. Clicking it adds a gray empty square at the canvas centre, selects it, and shows its rotation/scale controls. The empty square is framed in the margin paint like a photo and filled with the same translucent gray as an empty grid cell, so it lets 20% of what lies beneath show through. The same action is always available from the add-photo button at the left of the action bar.
- A free-form box has a fixed aspect ratio. It is square while empty; loading a photo adopts that photo's natural width:height ratio. Scaling keeps the ratio, and the box area is preserved when a replacement photo changes the ratio. A selected free-form box with a photo offers **Crop to square** (`crop_square.svg`) in the contextual actions (hidden while the box is still empty): it switches the box to 1:1 while keeping its area and turns the button red; a second click restores the photo's own ratio. A replacement photo stays square while the crop is active.
- **Photo border** (`border_style.svg`, second group of the contextual actions) — on by default. The photo is inset by the usual collage frame, the same 2 × border-thickness separation two adjacent grid photos show (10 px at the default 5 px). The frame is a ring cut through the canvas paint and stays aligned to the canvas even when the box rotates (the paint layer counter-rotates), so a gradient or the spots pattern continues through the border at the box's actual position; only the part hanging outside the canvas falls back to the sampled paint color. Transparent parts of the photo show the grid and canvas paint underneath. It follows the border-thickness slider and never squeezes the photo: the box minimum is the frame plus a 40 px image on every side, scaled by the box aspect. Scaling a box stops at that limit; raising the border thickness or switching the frame on grows any free box that would fall below the new minimum. Turning it off lets the photo fill the box edge to edge; the export matches either state, including transparency, rotation, and the painted frame. An empty free-form box is framed the same way: the paint ring surrounds the gray placeholder, follows the slider and the margin paint, and the export draws it too, so the box reads as a framed drop target before a photo arrives.
- **Fill photo background** (`background_replace.svg`, beside Photo border) — the toggle appears only for a free-form photo whose pixels include transparency, and starts off. Clicking it fills the box area inside the frame with the same canvas paint, so transparent pixels show the background instead of the grid and other free-form photos underneath; a gradient or the spots pattern continues the canvas at the box's actual position and stays aligned when the box rotates. It sits behind the photo, so opaque pixels are unchanged, and it follows the margin paint, the shuffle seed, and the border-thickness slider. Clicking it again removes the fill. Replacing the photo starts it off again. The export matches both states, and the JPEG gets the opaque paint instead of its usual transparent cut-out.
- Free-form boxes are moved by dragging the photo (or its selected overhang) anywhere on the canvas; their centre is clamped to the canvas so a box can always be grabbed again, while its edges may hang over the border. They are scaled by dragging the corner circle (distance ratio) and rotated by dragging the outer circle around the centre, with the same ±5° magnetic snap to multiples of 90° and the same snap-window mark swap as grid photos; both circles wear the same expand and rotate marks as the photo handles, on the same action-bar-colored disc with the same hover and press tones. Arrow keys nudge the selected box by 10 logical px (Shift 1 px).
- While selected, the part outside the canvas is shown at reduced opacity as a preview of the overhang; the part inside stays solid. When unselected, the overhang is clipped at the canvas edge, and the export always clips it. Selection borders, controls, and the translucent overhang never reach the export.
- Free-form boxes support delete, image selection (also by double-click or Enter/Space), and the one-step delete undo, and their replaced or deleted photos join the deleted-photo shelf like grid photos. Deleting a free-form box with a photo mirrors a grid box: the first delete only lifts the photo into the shelf and leaves the empty square in place (its centre and area kept, framing, crop, background, and rotation reset), and a second delete removes the box and offers the one-step undo.
- Free-form boxes can be scaled and rotated from the keyboard when their controls have focus: arrows scale/rotate, and `Home` resets rotation.
- **Add free text:** a second `edit_note.svg` button mirrors the free-photo button at the canvas's top-right corner, with the same 12 px gap and 32 px size, in both modes. It adds a gray square text box at the canvas centre, selects it, and opens its editor. The same action is always available from the add-text button at the left of the action bar, beside the add-photo one.
- A text box starts with the same 20%-transparent `#cfcfcf` backdrop as an empty grid cell at 80% opacity, but no frame. It begins as a square, then every saved text fits it around the words: the box keeps its centre (the canvas centre for a new box), adopts the measured width-to-height ratio of its lines, and keeps its type size, so it reads as a snug caption rather than a large empty tile. Scaling the box later scales the words with it. An emptied box returns to its square drop target at the same centre. The empty cell shows the centered `edit_note` hint instead of the add-photo hint.
- **Edit text** (`edit_note.svg`, first action group; also double-click, Enter, or Space) opens a centered modal dialog with a five-line textarea and **Cancel** / **Save**. Clicking anywhere outside the textarea or the two buttons — the panel background or the backdrop — cancels, and so does `Escape`; `Ctrl`/`Cmd`+`Enter` saves. Saving empty text removes the words and keeps the box as a square.
- The first saved text on a box whose backdrop is still the untouched default gray turns that backdrop off, so the words sit directly on the canvas paint. A background color picked in the text color menu counts as a chosen fill, so the first text keeps the backdrop on. Clearing the text restores the gray drop target. **Text background** (`background_replace.svg`) and **Text border** (`border_style.svg`) switch the backdrop and the canvas-paint frame on and off; the frame starts off for a text box, follows the border-thickness slider, and is drawn by the export like a photo frame.
- **Font** (`brand_family.svg`, second action group) opens a menu that only uses families already on the machine: **Sans serif** (the starting choice), **Serif**, and **Monospace** are always listed, then a separator and the installed families found at load (Arial, Helvetica Neue, Verdana, Trebuchet MS, Segoe UI, Georgia, Times New Roman, Courier New, Impact, Comic Sans MS). Availability is detected by comparing each family's text metrics with a generic fallback, so a missing family is hidden. Every item previews its own face, and every choice is a stack ending in a generic family so a box still renders if the font later disappears. Nothing is hosted, downloaded, or bundled, and the export sets the canvas font to the same stack. No offline system font picker exists: the Local Font Access API needs a secure context and a permission prompt, so it cannot be used from `file://`.
- **Text colors** (`colors.svg`) opens a menu with **Text color** (white by default) and **Outline color** (black by default, drawn as a text stroke that scales with the type size — 16% of the font size, about 4 px of visible halo at the default 48 px, so captions stay readable over busy photos), each with a chip and its own native color picker previewing live. While **Text background** is on, the same menu also shows **Background color** (the shared `#cfcfcf` until changed) and a **Background opacity** slider from 0 to 100% (80% to start); both paint the words' backdrop, preview live, and are used by the export. Switching the background off hides those two controls but keeps the stored fill, so it returns when the background is switched back on. The menu stays open while a picker or the slider is used. Both text colors and the font of the last edited text box are remembered and reused by the next new text box; the backdrop starts at the shared gray every time.

### Selection and contextual actions

- Clicking an image box selects it: 3 px border in the accent blue. The border turns red while one of the box's locks is active.
- Clicking the canvas background, the gray editor background, or pressing `Escape` clears the selection and empties the contextual actions. The row/column toggle, border-thickness button, margin-color picker, and Save stay visible.
- Double-clicking a box selects it and opens the image picker; a free-form text box opens its text editor instead.
- Selected-box actions:
  - **Delete** (`delete.svg`) — an empty box is removed outright: deleting the last box in a group removes that group, the selection is cleared, and the one-step undo appears. A box that holds a photo only loses the photo: the button is labelled **Remove photo**, the photo joins the deleted-photo shelf, the box stays in place and selected, and the cell returns to the empty state it had before — its own fill color and opacity (with the add-photo hint still hidden) or the default gray with the hint. Zoom, pan, rotation, and a ratio lock go with the photo; releasing a square or aspect lock keeps the pixel extents the way the lock button does. No undo button appears for a removed photo, since the shelf already holds it.
  - **Select image** (`image_search.svg`) — opens the browser file picker (`accept="image/*"`). The chosen file replaces the placeholder, cropped to the box aspect ratio and centered. Invalid or undecodable files show a visible error and leave the box unchanged.
  - **Lock square** (`crop_square.svg`) — hidden until the box has an image. Sets the box's free side so it is square and keeps that ratio as the group's cross-axis size changes (row height in row mode, column width in column mode). The active button is red.
  - **Lock aspect ratio** (`image_aspect_ratio.svg`) — hidden until the box has an image, then disabled only while its image ratio differs from an existing aspect lock in the group. Uses the image's natural aspect ratio to set the box's free side and keeps that ratio as the group's cross-axis size changes. When this is the group's only box, the group's cross-axis size is instead recalculated from the full flow-axis space available to a box, so the photo spans the canvas from margin to margin (top to bottom in column mode) whenever the other groups can still keep their 40 px minimums. Activating it resets the box's zoom and pan to the plain cover crop and hides the zoom circle until the lock is released; zoom changes are ignored while locked. Rotation stays available. The active button is red.
  - The two locks are exclusive: choosing one releases the other, and clicking the active lock releases it. While locked, boundary dragging involving that box is disabled; the group's cross-axis size remains adjustable in multi-box groups, while a single-box locked group keeps its group-boundary handles disabled.
  - A group with multiple boxes can have at most `n − 1` locks. The remaining unlocked box is forced to fill whatever space is left. Deleting the forced box can leave only locked boxes, so the last lock is released automatically to restore the rule.
  - Aspect-ratio locks are further limited to one ratio per group: the first aspect-locked image sets the group's reference ratio, and another box may be aspect-locked only if its image has the exact same width:height ratio. The `n − 1` cap still applies. Replacing an aspect-locked image updates the group; locks that no longer match the reference are released.
  - A group with a single box may lock that box. Its group-boundary handles are then disabled: a square lock keeps the box's free side derived from the group's cross-axis size, while an aspect lock derives the group's cross-axis size from the full flow-axis space and centres the box if the group minimum makes it shorter.
  - **Hide/Show box** (`visibility.svg` / `visibility_off.svg`) — always available. Starts visible; toggling it off keeps the box, its space, its image data, and its clickability, but clears the cell so the canvas paint shows through as a cut-out. An empty box hides its placeholder and add-photo hint too. The button switches to the crossed-eye icon and stays available so the box can be shown again. Hidden boxes keep their selection border; zoom, pan, rotation, and their chrome are inactive until the box is shown again. Loading a photo into a hidden box reveals it.
  - **Empty box color** (`colors.svg`) — appears only while the selected box is still empty, for grid and free-form boxes alike. It opens a small menu below the button with one color row (a chip plus **Color**, which opens the system picker) and an **Opacity** slider from 0 to 100% with a live `N %` readout. Both start at the cell's current paint — `#cfcfcf` at 80%, the values that reproduce the standard gray on a white canvas — and either one can be changed independently; the picker previews live and the popover stays open. The first change gives the box its own fill: the cell or free-form square repaints with that color and opacity (inside its frame, if it has one) and the centered add-photo hint disappears for good. The menu closes on Escape (restoring focus to the button), an outside click, or Tab, and whenever the selection moves to another box or the box receives a photo. Double-click, Enter/Space, and the image picker keep working unchanged; once a photo is loaded it covers the cell, so the color is ignored from then on. The export paints a recolored empty box with the same color and opacity over the canvas paint.
- The contextual area is split by a 1 px vertical divider: **Delete** and **Select image** on the left, the framing actions on the right — the two ratio locks (which only appear once the box has a photo) and **Hide/Show box** plus, while the box is still empty, **Empty box color** for a grid box; **Crop to square** (also only with a photo), **Photo border**, **Empty box color** while the box is empty, and (for a transparent photo) **Fill photo background** for a free-form box.
- A selected text box shows **Delete** and **Edit text** on the left, then **Font**, **Text colors**, **Text border**, and **Text background** after the divider. It has no ratio locks, visibility toggle, or empty-box color menu. While it holds words the delete button reads **Remove text** and clears only the words; an empty text box is removed outright and offers the one-step undo.
- **Margin color** (`format_color_fill_24dp_E3E3E3_FILL0_wght400_GRAD0_opsz24.svg`, always visible) — opens a small menu with **Fill** and **Gradient**, one or two direct color picker rows, and **Shuffle spots** while Random spots is the active style. The canvas starts with the **Warm Stone** preset as a top-to-bottom gradient (`#f5f2eb` → `#dfd6c7`), so the padding and gaps show it on load. **First color** alone shows while Fill paints the canvas and edits the fill color; **First color** and **Second color** show while a gradient does. Each row previews the color it edits in a small square chip. While a gradient is active, both the base menu and the stop panel end with the same preset grid: 20 chips in 4 rows of 5, each previewing its two stops diagonally (first color top-left, second bottom-right), with the category, name, and description in the hover title and accessible label. One click sets both stops, keeps the gradient style, marks the matching chip, and leaves the menu open.
  - **Fill** opens the system color picker and changes the canvas background, which is also the padding, gaps, and border color around the boxes. A chosen fill replaces any gradient.
  - **Gradient** opens a style menu with **Top to bottom**, **Left to right**, **Radial**, and **Random spots**. Choosing a style applies it with the current colors and opens the stop panel; the active style is highlighted when the menu is reopened. The color picker never opens on its own: each stop row opens it only when clicked, including the first switch from Fill.
  - **First color** / **Second color** in the base menu change a color with a single click. With a gradient active they open the stop panel and that stop's picker in the same gesture, so the gradient is not lost while recoloring. With Fill active only **First color** is listed, and it opens the fill picker instead, so the solid canvas color changes without a detour through **Fill**. The native picker previews live: the canvas and the chips follow while it is open, so dismissing the picker after a change keeps the last previewed color (there is no cancel rollback).
  - The stop panel lists **First color** and **Second color** as rows with a color chip, styled exactly like the base menu's color rows; each row opens its picker and previews its stop live. Top to bottom runs first→second downwards, Left to right first→second sideways, Radial places the second color at the centre and the first in the corners, and Random spots paints the first color as its base and lays five soft second-color organic shapes over it plus three offset first-color shapes that push back (115 px Gaussian blur). The scene is always composed at 1920 × 1080 or 1080 × 1920 — landscape uses the wide one, portrait and square the tall one — and centre-cropped to the format, so the pattern keeps its scale and the blur is never resampled. The spots bitmap is seeded, so the editor and the export show the same pattern. While Random spots is active, the margin menu also offers **Shuffle spots** (`shuffle_24dp_…svg`): it picks a new seed, regenerates the bitmap for the editor and the export, and leaves the colors and style untouched; the menu stays open for another shuffle.
  - The 3 px strip under the picker icon previews the paint: solid for Fill, first color on the left and second color on the right for every gradient style. Hidden grid cells stay transparent so the canvas paint shows through, and a free-form photo border samples the paint at the box's own position (the midpoint for Random spots).
  - The menu closes on Escape, an outside click, or Tab; choosing Fill closes it, choosing Gradient opens the style menu, and choosing a style opens the color panel. Escape restores focus to the picker button.
- **Border thickness** (`line_weight_24dp_E3E3E3_FILL0_wght400_GRAD0_opsz24.svg` rotated 90° clockwise, always visible) — opens a small popover below the button with a 0–100 px slider and a live `N px` readout. The value sets the canvas padding and every box gap together, so 5 px is the classic layout (10 px between boxes and to the canvas edge) and 0 px removes all margins: boxes touch each other and the canvas edge, and the margin color is no longer visible. It applies to both modes and both export formats. The slider is keyboard reachable; each step reflows the canvas once per frame. Escape, an outside click, or tabbing out closes the popover.
- **Save** (`download_24dp_E3E3E3_FILL0_wght400_GRAD0_opsz24.svg`, always visible) — opens a small menu below the button with **JPEG (.jpg)** and **PNG (.png)**. Both composite the canvas at the chosen format's logical size (1080 px on the shorter side) offscreen and download it as `collage-yyyy-MM-dd-HH-mm.<ext>` using the local save time; JPEG is encoded at 85% quality. Selection borders are not included; empty grid cells and empty free-form boxes export as the same 20%-transparent `#cfcfcf` fill (the canvas paint composited under it, which reads as the old `#d9d9d9` on white) without the add-photo hint; hidden boxes export as the canvas/margin paint (fill or gradient); photos are cover-cropped exactly as on screen.
- Only boxes have contextual actions; the row/column toggle, border-thickness slider, margin-color picker, and Save are global.

### Undo and the deleted-photo shelf

- Every deleted, removed, or replaced photo is copied into a browser-local shelf in `localStorage`: the ten most recent, newest first, deduplicated by a content hash so the same photo never fills two slots. The stored copy is downscaled to 800 px on its longer side (JPEG, 80% quality); deleting, removing, or replacing the same photo again moves its existing entry to the front instead of adding another. Storage failures (private mode, full quota) degrade to a session-only shelf instead of breaking the editor.
- The shelf is a second dark bar with square 40 px thumbnails cropped with `object-fit: cover`. On large screens it follows the canvas orientation: beside the left edge for portrait formats (9:16, 7:9) and along the bottom for landscape and square formats (16:9, 5:4, 1:1). Below 700 px wide it always stays along the bottom. It hides before a format is chosen and while it is empty, and scrolls without a visible scrollbar when ten thumbnails do not fit.
- A **Delete all** button (`delete.svg`) sits at the end of the shelf: the right end of a bottom bar, the bottom of a left bar. It is always visible while the shelf is shown. Clicking it empties the shelf, removes the stored photos from `localStorage`, hides the bar, and leaves the collage itself untouched.
- Clicking a thumbnail inserts the stored photo into the currently selected box; the photo it replaces joins the shelf in turn. With no box selected it shows a short hint instead. The shelf never adds, removes, or reorders boxes on its own, and the selected box keeps the selection.
- Deleting an *empty* box shows an **Undo** button (`undo_24dp_…svg`) at the far left of the action bar. It restores only the last deleted box: same group, index, and weight, with its empty-cell fill, and selects the restored box. The button hides after that one undo. Removing a photo from a box is not an undo step; the shelf already holds the photo.
- Any structural change discards the pending undo: another box delete (which becomes the new undo target), adding a box or group, or switching row/column mode. The shelved photo stays available. Replacing a photo, removing a photo, or editing zoom, pan, rotation, or locks does not discard the undo.
- The in-memory image of the pending undo is kept alive (its object URL is not revoked) until the undo is used or discarded.

### Direct manipulation

- **Zoom a photo** — selecting a box that has a photo shows a 28 px circle in its bottom-right corner (screen-sized at any canvas scale). It shows the expand mark (`zoom_out_map.svg`) at 24 px — the add-button icon size — on a disc filled with the action-bar color; hovering lightens it to the action-bar hover tone and pressing deepens it to the action-bar click tone, with the light mark unchanged and no glow. An invisible 40 px grab pad extends up-left from the dot so the target stays finger-sized without changing the visual. Pointer-drag the circle away from the box centre to scale the photo; the zoom factor follows the distance ratio, so pulling to twice the starting distance shows 2×. 1× is the cover crop for the current rotation; dragging inward goes below 1× until the whole rotated photo fits in the box (the canvas background shows around it), and outward stops at six times the unrotated cover. The range is recalculated when the photo is rotated or the box is resized. The circle is a `role="slider"`: arrow keys zoom and `Home` resets to the cover crop. While the box's aspect-ratio lock is active, the zoom circle is hidden and the state ignores zoom changes.
- **Rotate a photo** — a second 28 px circle sits 14 screen px outside the same corner, in an unclipped chrome layer so it stays reachable when the box touches the canvas edge. It shows the rotate mark (`rotate_left.svg`) on the same action-bar-colored disc, with the same hover and click tones as the zoom circle and no glow. Its invisible grab pad extends 40 px down-right, away from the zoom pad so the two targets do not fight. Drag it around the box centre to rotate the photo in degrees. Rotation snaps magnetically to multiples of 90° while the raw angle is within ±5° of one; outside that window the raw pointer angle is used for smooth free rotation. While the handle is dragged, it swaps to the `rotate_90_degrees_ccw` mark whenever the raw angle is inside the snap window and returns to the rotate mark outside it; an idle handle always shows the rotate mark, even at 0° or 90°. At 1× the image scales up just enough that its rotated rectangle still covers the box, so no gap appears; zooming out below 1× then trades that cover for showing more of the photo, down to the fit scale. Arrow keys rotate ±1° (Shift ±15°) and `Home` resets. The rotation is stored per box in the (−180, 180] range and resets when the photo is replaced.
- **Pan a photo** — while the box is selected, pointer-drag the photo itself, or the canvas background under its ghost, to move it within the crop. Panning stops at the image edges, so it never reveals more background than the current zoom already shows. Offsets are stored as −1…1 shares of the rotation-aware slack on each screen axis, so the framing survives row and box resizes and is preserved through export.
- **Ghost overlay** — while an image box is selected, the full photo is drawn at 32% opacity behind the box but above its siblings, showing the parts outside the crop as a drag reference. It follows the zoom and rotation. It is DOM chrome: the export draws only the cropped, zoomed, rotated photo. The ghost and both circles vanish as soon as the selection clears or moves to another box.
- **Drag a box** — planned, not built: pointer-drag on a selected box reorders it within or across groups. Until reordering lands, a drag on a selected photo pans it instead.
- **Resize a box** — hovering the white gap between two boxes in the same group highlights it with a 2 px accent line (vertical in row mode, horizontal in column mode) and shows the matching column- or row-resize cursor. The grab band is measured in screen pixels (8 px around the boundary for a mouse, 22 px for touch) and extends over the boxes, so it stays usable when the canvas is scaled down. Dragging moves that boundary, trading width or height between the two boxes while every other box keeps its size. Both boxes are clamped to the 40 px minimum. The cross-axis size always follows the group. A boundary touching a locked box is not draggable.
- **Resize a group** — hovering the white gap between two groups highlights it with a 2 px accent line (horizontal between rows, vertical between columns) and shows the matching row- or column-resize cursor. The same screen-sized grab band widens for touch. Dragging moves that boundary, trading height or width between the two adjacent groups while the canvas size and every other group stay fixed. Both groups are clamped to the 40 px minimum. Locked boxes recalculate their free side from the new cross-axis size so their ratio is preserved. A boundary adjacent to a single-box locked group is not draggable.
- **Lock a ratio** — square locks use 1:1; aspect locks use the natural image ratio. The box's free side is derived from the group's current cross-axis size, so resizing the group keeps the ratio. Unlocked siblings in the group reflow; other groups are untouched. Releasing a lock preserves the box's current pixel size and makes its boundaries draggable again.
- Use pointer events and capture the pointer only once the ~3 px movement threshold is crossed, so a tap still selects the box (or a boundary tap does nothing) instead of being swallowed by a drag.

### Reflow model

Boxes flow like flex items with `flex-grow`; the canvas never resizes. Row mode is the model below; column mode is the same math with the flow and cross axes swapped.

- Canvas content width = `canvas-w − 2 × pad`. Content height = `canvas-h − 2 × pad`.
- Each group has a flow-axis **weight** (row height or column width); each box has a cross-axis **weight** (box width or height).
- Group extent = `flowTotal × weight / Σ groupWeights`, minus `2 × gap` for the box extent.
- Box extent = `(crossTotal − 2 × gap × n) × weight / Σ boxWeights` in its group. Each box reserves a gap on both sides, so two adjacent boxes show twice the gap between them and every outer edge keeps one gap beyond the canvas padding.
- A locked box requests the group's cross-axis size multiplied by the lock ratio (inverted in column mode so the image's width:height proportion still holds) instead of using its weight. Unlocked boxes share the remaining cross-axis space by weight. A multi-box group always leaves at least one unlocked box, which absorbs the remainder. If the locked sizes cannot fit, they shrink proportionally; if every box in a group is locked and the group is smaller than the canvas, it stays left/top-aligned rather than stretching and breaking the ratio.
- A group's only box with an **aspect** lock is the exception: its cross-axis size comes from the full flow-axis space available to a box, so the box fills the canvas from margin to margin (top to bottom in column mode). Fitted groups claim their flow-axis extent first; the remaining groups share the rest by weight and stay at or above 40 px. When the fitted extents cannot all fit, they are scaled down proportionally and every other group stays at its minimum. A fitted group whose ideal extent would be shorter than 40 px keeps the 40 px group and centres the full-size box in it. If every group is fitted and there is space left over, the stack stays start-aligned and the canvas background shows beyond it.
- Adding a box gives it the group's mean weight; adding a group gives it the mean group weight and renormalizes the stack.
- Removing a box or group renormalizes the remaining weights.
- Resizing redistributes weight only between the dragged element and its siblings/adjacent groups.
- Clamp with minimums (group 40 px, box ≈ 40 px) so nothing collapses to zero.
- Round to whole logical pixels; give the last box in a group the rounding remainder so edges stay flush. Never let a gap or box overflow the padded content box.

The result: any structural or size change reflows the whole canvas to fill the same fixed area, with no scrolling inside the canvas.

## How to run and verify

- Quickest: open `index.html` in a browser — that satisfies the offline requirement.
- Dev server: `python serve.py` → http://localhost:8000 (add `-p 8080` for another port, `--no-open` to skip launching a browser). Stdlib only, no install.
- No test runner; verify manually and say what you checked.
- DevTools console must be clean and the Network tab must show no requests.

## Code conventions

- Modern JavaScript (ES2020+): `const`/`let`, arrow functions, template literals, `'use strict'` per file.
- `kebab-case` for ids/classes, `camelCase` for JS, `UPPER_SNAKE_CASE` for constants.
- All user-facing text lives in `js/i18n.js`; use `I18n.t()` in scripts and the `data-i18n*` attributes in markup.
- One source of truth for state (`state.js`). DOM is a render target; never read editor state back out of the DOM.
- Separate "mutate state" from "render". Route undoable mutations through one commit function.
- Use `requestAnimationFrame` for visual updates; throttle pointermove work; avoid layout thrash and per-frame `toBlob()`.
- Release object URLs and `ImageBitmap`/canvas references when boxes are removed or photos replaced.
- Comments explain *why*. No commented-out code.

## UX and accessibility

- Every icon button is a real `<button>` with an `aria-label`, a `title` tooltip for mouse users, and a visible hover/focus state.
- Keyboard: `Tab` moves through controls; arrow keys move selection between boxes; `Delete`/`Backspace` deletes the selected box, or removes its photo or text when it holds one; `Enter`/`Space` opens the image picker or, for a text box, the text editor; `Escape` deselects.
- Announce selection and error messages via an `aria-live` region.
- Show a friendly empty state when no groups remain, using row or column wording; fail visibly on unsupported or undecodable images.
- Respect `prefers-reduced-motion` for transitions.

## Performance and limits

- Keep drag/resize at ~60 fps with 20 boxes on a mid-range laptop; update existing group/box geometry during a drag instead of rebuilding the tree.
- Prefer `createImageBitmap` where available; never block on decoding.
- Downscale very large photos for on-screen rendering while keeping originals for export.

## Open questions

Defaults chosen for v1 — change them here before implementation if wrong:

1. **Drag semantics:** reorder by weight, not free placement. Free positioning would conflict with the flex-flow requirement.
2. **Canvas size:** 1080 px on the shorter side, longer side from the chosen format (9:16, 16:9, 7:9, 5:4, or 1:1), matching the export target.
3. **Resize axes:** in row mode, boxes resize horizontally and rows vertically; column mode swaps those axes. The mode toggle owns the choice, so there are no per-box vertical handles.
4. **Persistence and undo/redo:** full collage persistence and general undo/redo are still planned. The deleted-photo shelf and its one-step delete undo are part of v1; the weight-based state keeps broader persistence cheap to add later.
